## 二、脑的动力学：速率模型

```python
# endfield_fly.py 主循环里
for _ in range(args.steps):          # 默认 10 内步
    _y = W @ r + drive
    if fod is not None:
        _y = _y + fod["mb"].contribution(r)   # 蘑菇体的输出贡献
    r = (args.a * r + args.b * np.tanh(_y)).astype(np.float32)
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `--steps` | 10 | 每拍内步数 |
| `--a` | 0.5 | 泄漏系数（`r` 的保留比例）|
| `--b` | 1.0 | 输入增益 |
| `--hz` | 2.5~3.0 | 决策频率 |

**为什么用速率模型不用脉冲模型**：211,577 个神经元在 400 ms 内
要做 10 次稀疏矩阵乘，LIF 的仿真成本高一个量级，而且对
"行为艺术"这个目标没有额外收益。速率模型的表达能力已经够了。

## 三、★ 读网络输出：`w @ r[kc]`，不是 `r[mbon].mean()`

**这是这个概念上最容易搞错的一处。**

```python
# ✗ 错的
mbout = r[mbon_idx].mean()        # MBON 神经元自己的活动

# ✓ 对的
mbout = w[mbon_idx][:, kc_idx] @ r[kc_idx]   # 网络**投给** MBON 的输入
```

**为什么**：MBON 的活动 `r[mbon]` 是它被上一拍驱动后的状态，
**它已经被 `tanh` 压过、被泄漏拉过**。而学习改的是 KC→MBON 的连接权重 `w`，
所以真正反映"学了多少"的是 `w @ r[kc]`。

实测差别很大：用错的时候，权重明明在漂移，但 `r[mbon]` 几乎不动，
看起来像"学习没生效"。

## 四、学习：三因子规则，只改 KC→MBON

```python
# mb_learn.MushroomBodyLearner.step()
Δw = eta * DA * relu(x_pre - theta)
```

| 因子 | 来源 |
|---|---|
| `x_pre` | 突触前（KC）活动 |
| `DA` | 多巴胺（DAN 给出的全局/分区信号）|
| `theta` | 阈值（跟资格迹一起衰减）|

**三个刻意的限制**：

1. **只改 KC→MBON**，不改别处。
   全脑 2600 万突触全都在线学习，一是算不动，二是会崩。
   蘑菇体是果蝇身上研究得最清楚的"学习器官"，改它就够讲这个故事了。

2. **`relu(x_pre - theta)` 而不是 `x_pre`**。
   只有"足够活跃"的 KC 才参与学习——稀疏化，防爆炸。

3. **权重 clip 到 ±3.0**。
   不 clip 的话几轮之后会出现极端权重，网络直接饱和。

### 多巴胺从哪来

| 事件 | 信号 |
|---|---|
| 打死 | `+reward`（`--forage-eta` 相关）|
| 挨打（血条相对下降 / 受击红晕）| `-punish` |
| 打到（小额）| `+hit_reward`，有 `--hit-cooldown` 防白送 |
| 任务完成（★ 默认关）| 连发 50 次 |

**`--hit_reward` 必须远小于「打死」的大奖**，否则它会停在打到那一层不往前。

### 分区多巴胺

```python
mb = MushroomBodyLearner(W, kc_idx, mbon_idx, ...)
# 内部：DAN → MBON 的行剖面做 k-means(k=4)
mb.group_scores(r)   # 4 个分区的输出
```

4 个分区（`out/mb_groups.npz`）→ 对应 4 个技能槽。

> 组 0 天生对应"主攻"——这个对齐是**刻意的**：
> 学到的正向关联直接把主攻推上去。

## 五、饥饿内稳态

```python
class Hunger:
    h        # 0~1，0=饱，1=饿
    rise     # 每秒回升（--hunger-rise，默认 0.030）
    eat      # 每次进食下降（--hunger-eat，默认 0.35）
    hold_left  # "吃饱"窗口倒计时（秒）
```

**它同时乘到三个地方**：

```python
odor_gain()  = 0.3 + 1.0*h     # 气味输入增益
drive_gain() = 0.2 + 0.8*h     # 觅食驱动力增益
da_gain()    = 0.1 + 0.9*h     # 多巴胺增益
```

**为什么三处都要乘**：饿不只是"更想打"，它还
"更闻得到"（odor_gain）、"更学得动"（da_gain）。
这是果蝇真实的调质机制——饥饿不是一条控制线，是一个全身状态。

### 吃饱窗口（任务完成时）

```python
hg.clear(hold_sec=10.0)   # h → 0，并 10 秒不涨
```

**用倒计时不用时间戳**：`step()` 只拿到 `dt`，拿不到绝对时间。
倒计时天然对 `dt` 正确——主循环降频、卡顿、暂停恢复都不会算错。
用墙钟的话，果蝇暂停 5 分钟再恢复，那 10 秒窗口就被"跳过"了。

## 六、★ 技能选择：先天语义 + 学习微调

### 为什么必须有"先天"这一层

**果蝇从画面上看不出技能是干什么的**（没有 mod，只有画面）。
光靠结果去学：

- **"回血"学不出来** —— "没挨打"不是信号
- **"格挡"也学不出来** —— 同上
- **"增伤"学不出来** —— "后续打得动"不是信号

**这是信号问题，不是算法问题。**

所以技能语义当**本能**写进 `innate_priority()`，
学习只在上面微调优先级。

### 四个槽的"角色"可配

```bash
--role-1 .. --role-4    # attack / buff / block / heal / gather / weaken / none
--key-skill1 .. 4       # 每个槽按哪个键
```

两者**独立**：换配队只改键，换打法则只改含义。

| 角色 | 触发条件 | 优先级 | 为什么 |
|---|---|---:|---|
| `attack` 攻击 | 永远在线（底）| 0.55 + 0.45h | 越饿越想打 |
| `weaken` 挂削弱 | 开战前段（<4.5s）| 1.45 | |
| `buff` 增伤 | 开战中段 | 1.45 | |
| `block` 格挡 | **中了段血**（`heal_hp`~`+0.25`）| 1.55 | 预防，不是补救 |
| `heal` 回血 | **血低于回血线** | 1.6 + 1.5·缺 | 补救，最高优先 |
| `gather` 聚怪 | **开战那一拍** | 1.55 | 晚放没意义 |

**★ 格挡挂在"中段血"而不是"低血"，是唯一真正的新设计。**
"血低就放保命技能"原来就有；格挡要体现价值，就得在**还没到危险线**时用——
预防 vs 补救的分工，不是同一件事的两种说法。

### ★ 1.45 / 1.6 这些数字不是拍脑袋的

> 主攻的先天上限是 **1.0**，学习偏移上限是 **±0.30**，合计 **1.30**。
>
> 所以 **1.45 > 1.30** → 轮换阶段稳稳选中，学不坏。
> 所以 **1.6 > 1.30** → "血低就回血"是**学不坏的保命规则**。
>
> 第一版给的是 1.00/0.90（比主攻还低或持平）——
> 实测 31 次技能里 30 次都是主攻，**轮换等于没发生**。

### 学习偏移必须**有界**

```python
p = p + learn_gain * np.tanh(g / (2.0 * spread))   # 夹进 ±learn_gain
```

第一版写的是 `learn_gain * g / mean|g|`，**没有上界**——
实测组 0 被强化后偏移到 0.92，直接盖掉了"血 25% 该回血"
（保命规则的先天差距只有 0.14）。

## 七、常见故障对照

| 症状 | 先查 |
|---|---|
| 什么都不动 | `r` 是不是恒为 0（零基线的驱动会让网络静默）|
| 只放主攻，不轮换 | 先天优先级被学习压过去了 / 角色配置错了 |
| 血低不回血 | `heal_hp` 设太高 / 回血槽配成了 `none` |
| 学不到东西 | `--forage-eta` 是否为 0 / 多巴胺是不是没投递 |
| 权重漂移爆涨 | clip 被去掉了 |
