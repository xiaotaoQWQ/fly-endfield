## 2026-11-01 · 修「HOME 接管失灵」：属性赋值没转发给内层闸门

**现象**：按 HOME 没反应 / 接管了但果蝇还在按键。

**根因**：接管用的是 `ex.on = True`，但 `ex` 现在被 `_DodgeGate` 包了一层；
`_DodgeGate.__getattr__` 只转发**读**，`ex.on = True` 这种**写**落在包装层自己身上，
里面的 `_TakeoverGate.on` 永远是 False → 闸门根本没关。
（`hasattr(ex, "on")` 反而返回 True，因为读是转发的 —— 所以不会报错，只会静默失效。）

**改哪**（_DodgeGate）：
- 加 `__setattr__`：自己那几个字段（_inner/lock/until/blocked/moved）正常写，
  其余属性**转发给内层**（`ex.on = True` → `_TakeoverGate.on = True`）
- 单测（把类抠出来跑）：
```
1) 正常按键: sent          inner.sent=[1]
2) g.on=True → 外层True 内层True   接管中按键: BLOCKED
3) g.on=False → 内层False
4) 闪避后锁键: 按键 None / 再 dodge None; 1.3s 后恢复 sent
```

**教训**：包装层只要不转发 setattr，任何「往外层对象写状态」的老代码都会静默失效。
这和前面「闸门漏一条路径」是同一类问题 —— 包装器要么全透传，要么别包。

## 2026-11-01 · 闪避锁定期语义确认 + 锁定期内禁止再次闪避

**语义（用户明确）**：触发闪避（空格+Shift）后的 1.2 秒内 ——
**可以按 WASD，其他一律不许按**。

锁定期的完整矩阵：
```

再次闪避          ❌ 禁止（本轮新增：dodge() 在锁定期内直接返回）
松键 release_*/*_up ✅ 永远放行（卡键比不发更糟）
```

## 2026-11-01 · 技能概率到底谁最大？—— 实测算给你看 + 暴露 --skill-learn-gain

**问题**：「如果真果蝇选，S1 的概率最大吗？」

## 2026-11-01 · 修「回血不触发」：hp 类型判死 + 半血阈值可调 + 血危兜底

**现象**：血量低于半血也不放回血技（槽 3）。

**根因**：`innate_priority` 里写的是
```python
hp_ok = isinstance(hp, float) and hp == hp      # ← 只认纯 Python float
low   = hp_ok and hp < heal_hp
```
`auto_outcome` 返回的 `auto_hp` 很可能是 **np.float32**（也可能是 int / 百分数 / 字符串），
`isinstance(x, float)` 直接 False → `low` 永远 False → **回血这一路等于关闭**。
（面板上表现为「分区」正常、技能也放，但永远不放回血槽。）

**改哪**（mb_learn.py）：
- hp 解析改成 `float(hp)` + 容错：np.float32 / int / "0.30" / 43(百分数) 全部接受；
  `>1.0` 自动当百分数除以 100；NaN/None/乱值 → `hp_ok=False`
- `heal` 优先级底从 1.6 → **1.75**（主攻上限 1.30，保证保命压过一切）
- 新增 `hp_low_hint`：**血读不到但 ONNX 报「血危」**时也当低血
- `endfield_fly.py`：传 `hp_low_hint=sum(st_onnx["hp_danger"]) > 0`；
  启动时打印「回血阈值：血 < 50% 触发回血槽（--heal-hp 可调）· 每槽冷却 6.0s」

**实测（select_skill 直调）**：
```
hp=0.30 / np.float32(0.30) / 30 / 43.0 / "0.30"  →  槽 4（回血）
hp=None + 血危标签                               →  槽 4
heal_hp=0.5 → 血 0.40 回血 / 0.55 主攻            ← 半血阈值生效
heal_hp=0.65 → 血 0.55 也回血                     ← 阈值可调
```

## 2026-11-01 · 接管键换 HOME + 修「按了没反应」（短按在 2.5 Hz 下被整拍错过）

**为什么**：实机按 `0` 完全没反应。两个原因叠在一起：

- `--takeover-key` 默认 **0 → home**；`COMBAT_VK` 增加 `home(0x24)` / `f12(0x7B)`

## 2026-10-31 · 多角色连携提示并存时「追加按」（原来只按一次）

**为什么**：上一轮 77 秒里 3 次 `NG 连携没生效`，原因是**多角色提示并存**：
判据是「`m_combo` 上升沿才按一次」，而三个角色同时亮提示时 `m_combo` 一直是 True，
第二、三个提示永远等不到上升沿 → **一整段只按了一次**，剩下的连携全被浪费。
而且此时提示确实还在，效果自检会把「按到了但也还有别人的提示」误判成 `NG`。

**改哪**（`endfield_fly.py`）：
- 新增 `--combo-repeat`（默认 **0.7 s**）：提示还在就隔 0.7 秒**再按一次**
- 新增 `--combo-repeat-max`（默认 **4** = 队伍人数上限）：一次提示事件最多连按几次
- 效果自检改成「按满 repeat-max 次后提示还在才判 NG」；NG 之后**加锁**，
  等提示消失才解锁（否则会 4 次→NG→再 4 次地刷）
- 日志区分 `提示·菱形` / `追加·菱形`，一眼看出是首个提示还是并存追加
- `--combo-repeat 0` = 回到旧行为（只按上升沿）

**怎么验**（离线状态机模拟，`_simcombo.py` 复刻同一套判据）：
```
单角色提示 0.8s      → 按 1 次 · OK 1 · NG 0
三角色并存 3.2s      → 按 4 次 · OK 1 · NG 0   ← 原来只会按 1 次
提示一直不消失 12s   → 按 4 次 · NG 1 · 之后锁住不再刷
```
实机：`python -X utf8 endfield_fly.py --seconds 3 --dry --forage`（退出码 0）

**坑**：**「信号一直为真」不等于「只要按一次」**。上一次的坑是电平触发太密，
这一次的坑是上升沿太稀 —— 判据要和「一个提示 = 一次按键」这个语义对齐：
提示持续 = 还有别的角色在等，应该**再按**，而不是当同一个提示忽略。

→ **纯像素阈值不行**，会变成新的「乱按」。正确的主视角信号是果蝇自己的
**LPLC2/LC4（311 个 looming 神经元）** —— 视野里有东西加速膨胀就放电，
这条回路本来接技能键，现在**也接闪避**。

**改哪**（`endfield_fly.py`）：
- `--dodge-src {onnx,cortex,both}`（默认 `both` = 两路取或；要彻底不用 MaaEnd 就 `cortex`）
- `--dodge-z`（默认 1.5）：LPLC2/LC4 的 z 分超过它就闪（技能键用 1.0，闪避更保守）
- 主视角这一路三道门：**上升沿 + 战斗中(m_on) + --dodge-cool**
- 日志 `★ 闪避 ← 主视角 looming z=+1.83`（和 ONNX 那路的 `→ Shift 点一下` 区分开）
- 收尾统计：`闪避 主视角N次/ONNX M次 · looming z最大±x.xx（≥0.5/1.0/1.5/2.0 各多少拍）`

**怎么验**：
```bash
python -X utf8 endfield_fly.py --seconds 3 --dry --forage   # 退出码 0
```
实机跑一轮后看收尾那行：
- `z最大` 只有 0.6~0.9 → 把 `--dodge-z` 降到 1.0
- z 频繁过 2.0 但很少真挨打 → 升到 2.0，或加 `--dodge-cool 2.0`
- 要完全关掉 MaaEnd 那一路：`--dodge-src cortex`

**坑**：主视角在战斗中一直很「花」（p90 帧间差 63/255），
所以**没有上升沿和战斗门**的任何主视角判据都会退化成乱按 —— 这次先把门装好。

## 2026-10-31 · 连携 E「乱按」：兜底默认关 + 加生效自检

**为什么**：实机一轮 60 秒按了 **51 次 E**，其中 **47 次是兜底**（`--combo-cool-full 0.8`）。
根因：ONNX 报 `满的槽 [0,1,2,3]` 几乎一直成立（槽一直是满的），而兜底是**电平触发**
→ 每 0.9 秒按一次。用户看到的就是"E 在乱按"。
真正由提示触发的只有 4 次，且**全部来自 `提示·菱形`** —— 菱形这一路是对的。

**改哪**：
- `--combo-cool-full` 默认 **0.8 → 0（关）**；开了也只认「满的槽变多」的**上升沿**，不认电平
- 新增**效果自检**：提示按下后 1.2 秒看提示有没有消失 → 日志 `OK 连携生效` /
  `NG 连携没生效`，收尾统计 `(成 x/败 y)` —— 这才回答得了"按对没有"
- 「连携技连按 4 次…键位设错了」的警告**只统计提示触发的按**（兜底不再触发误报）
- 按 E 的日志加菱形原始分（`分 0.00, 菱 0.96`），一眼看出是哪一路触发
- 顺手补回被上一次改动吃掉的 `--combo-cool` 参数定义（少了它启动就 AttributeError）

**怎么验**：
```bash
python -X utf8 endfield_fly.py --seconds 3 --dry --forage   # 退出码 0
```
实机日志里 `★ 连携技 → 按 E` 应该**只在真提示出现时**出现（一分钟 0~5 次，而不是 51 次），
紧接着应出现 `OK 连携生效`（提示消失）或 `NG 连携没生效`（提示还在）。

**坑**：兜底这种东西，"没提示按 E 在游戏里没副作用"只对**游戏**成立 ——
对**行为**不成立：电平触发 + 常年为真的信号 = 每 0.9 秒一个动作，用户一眼就是"乱按"。
凡是「信号几乎一直为真」的量，判据必须写成**沿**，不能写成电平。

## 2026-10-30 · 顺手修：不带 --forage 时第一拍就崩（UnboundLocalError: _m）

**为什么**：`_m = fod["mb"]` 只在 `fod is not None`（= 开了 --forage）的分支里赋值，
但下面 `if args.ab_mushroom:` 是**降级到外层缩进**的，默认 ab_mushroom=True ——
于是不带 `--forage` 跑，第一拍就 `UnboundLocalError: cannot access local variable _m`，
整个程序退出。带了 --forage 的人永远看不到，所以一直没被发现。

**改哪**：`endfield_fly.py` 主循环 → `if args.ab_mushroom and fod is not None:`

**怎么验**：`python -X utf8 endfield_fly.py --seconds 3 --dry`（**不带** --forage）
→ 以前第一拍就 traceback，现在能跑完 9 拍正常退出（退出码 0）。

**坑**：这属于「对照组开关默认开 + 变量在别的分支里赋值」的组合 ——
对照组这种东西默认关掉更安全，或者赋值提到分支外面。

## 2026-10-09 · 修鼠标滚轮静默改键位

**为什么**：用户报「为什么会按 q」。日志显示 `combo_key` 被改成了 `q` ——
`ttk.Combobox` **悬停时会被鼠标滚轮改值**，用户一边玩游戏一边滚滚轮，
鼠标扫过面板就把键位改掉了。于是按错键 → 连携技提示不消失 →
检测器一直为真 → **每拍都按** → 7 秒连按 11 次。

**改哪**：`app_window.py` 下拉框 `bind("<MouseWheel>", "break")`；
面板常驻一行「键位」；`endfield_fly.py` 连按 4 次就警告

**怎么验**：面板最上面能看到当前键位；故意把 `combo_key` 设错时，
日志 4 次后出现 `⚠ 连携技连按 4 次（键「x」）提示仍不消失`

**坑**：先做了排除 —— 建窗口时**一行 `[键位]` 都没有**，
说明不是"初始化时自己触发"，而是真实的鼠标操作。
**先分清是"代码错"还是"用户操作"，再动手修。**

## 2026-10-09 · 按键/技能含义可配 + 清空记忆

**为什么**：技能语义原来写死成「1 伤害高 · 2 挂削弱 · 3 增伤 · 4 回血」，
换配队就全错。而且错得很隐蔽（照常按键、照常打，只是打在错的地方）。

**改哪**：
- `--role-1..4`（attack/buff/block/heal/gather/weaken/none）
- `--key-skill1..4`
- `--key-ult`（逗号分隔的键序列）
- `mb_learn.innate_priority(roles=...)`
- `MushroomBodyLearner.reset()` + 面板「清空记忆」

**怎么验**：
```
攻/增/挡/回 血60%  [1.00 0.00 1.55 0.00] -> 3   格挡
攻/增/挡/回 血30%  [1.00 0.00 0.00 2.20] -> 4   回血
聚怪/攻击/无/无 开战 [1.55 1.00 0.00 0.00] -> 1   聚怪
全 none（事故配置）  [0.00 0.00 0.00 0.00] -> 1   兜底不空转
```

**坑**：下拉框存的必须是**值**不是**显示文字**。
写显示文字的话 argparse 收到的是中文长句 ——
**表面上不报错，但语义全丢**。

## 2026-10-09 · 连携技标定重做（原来抓错了 UI 元素）

**为什么**：用户报「特定角色 E 不释放」。录屏 951 帧离线回放，
发现旧模板的最高相关只有 **+0.460**，而 `>=0.45` 只有 **2/951 帧** ——
**99.8% 的时间里它根本看不见提示**。把帧里的 E 徽标和旧模板并排一比：
抓的是**队友圆形头像上的另一个徽标**，完全不同的 UI 元素。

**改哪**：
- `templates/combo_e.npy` 换成真 E 徽标（**30×28**，内容尺度）
- `ComboMarker.step()` 不再降采样
- `REGIONS["combo"] = (1400, 590) 200×100`（收紧）
- 阈值 0.60 → **0.50**（8 种分辨率实测）

**怎么验**：951 帧回放，旧标定 **2/951** 命中，新标定 **115/951**，
真提示 +0.75~+1.00、噪声底 +0.333。

**坑**：标定必须**离线回放验证全部帧看分布**，
不能只看"当时抓到了"。当初只测了"真提示 +0.606、假的最大 +0.267"就收工，
那组数字**只对当时那个场面成立**。

## 2026-10-09 · 整帧抓取（LiveFrame）+ 多分辨率验证

**为什么**：改之前每拍抓 **7 次**屏幕，两次之间隔十几毫秒，
而游戏是 60 fps 在跑的 —— "血条还剩 30%"和"红环亮着"
**可能不是同一时刻的状态**。

**改哪**：新建 `live_frame.py`；主循环所有 HUD 改成从同一帧切片

**怎么验**：整屏 87 ms vs 7 个区域 105 ms —— **更一致，还略快**；
8 种分辨率召回率 97%~100%（阈值 0.50）

**坑**：眼睛线程**不走**这条路 —— 它要 30 Hz，而整屏抓一次 87 ms
（最多 11 Hz）不够。**眼睛要快，HUD 要准**，两个需求本来就冲突。

## 2026-10-09 · 对照组（消融实验）

**为什么**：项目的两条底线里，第一条是"它得真的在控制那个角色"。
**光靠嘴说没用 —— 得能把某个脑区关掉，看行为变不变。**

**改哪**：`live_tune.TOGGLES`（7 个开关）+ 面板复选框；
`endfield_fly.py` 各处的 `args.ab_*` 判断

**怎么验**：全关时 `饥饿值 h` 锁在 0.500；关掉「连接组」后
神经网络输出变成固定种子的随机数，行为明显变乱

**坑**：「运动输出关掉」是在执行器外包一层空操作，
第一版拦的是 `("apply","press","hold","click")` ——
**漏了 `combat_press` 和 `combat_hold_down`**，那才是打怪真正用的通道。
**「关掉某个功能」要实现成「单一闸门」，不是「在每个出口加判断」。**
