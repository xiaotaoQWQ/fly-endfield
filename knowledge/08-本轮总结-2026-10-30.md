## 一、做了什么

### 1. 识别层：换成 MaaEnd 的 YOLO11s

**起因**：用户提出「把识别换成 maaend，这个识别比自己做的屏幕抓取要好」。

**调研结论（三条，都有实测）**：

| 方案 | 结论 |
|---|---|
| A 整体集成 MaaFramework | ❌ **不可行** —— `maafw` 无 cp314 wheel，Python 3.14 装不上 |
| B 换 OCR | ❌ **方向错** —— Windows OCR 在这类小字上不稳；而且 MaaEnd 自己也不用 OCR 判状态 |
| C 借它的模型 | ✅ **可行** —— 只需要 `onnxruntime`，不需要 maafw |

**最终实现**：`onnx_detect.py`（约 450 行）
- 预处理严格照 `MaaFramework` 源码（letterbox + 填充 114 + BGR→RGB + CHW + ÷255）
- YOLO11s · 640×640 · 22 类 · `[1, 26, 8400]` 输出
- 自己做 NMS
- **独立线程**（`OnnxThread`，6 Hz），主循环只 `submit`/`read`

**关键数据**：

```
推理中位      96 ms（离线） / 125~250 ms（实机，视 CPU 争用）
2.5 Hz 预算   400 ms
截图          87 ms
```

### 2. ★ ONNX 到底比老模板好多少（逐帧验证）

拿 428 帧真实录制，同一帧跑两套识别：

| | 旧模板 | ONNX |
|---|---:|---:|
| 触发帧数 | 7 / 428 | 2 / 428 |
| 真提示（人工核验） | 2 | 2 |
| **误报** | **5**（corr 0.514~0.645，全在阈值边缘） | **0** |

**误报的那 5 帧，框里是纯背景或 Windows 桌面** —— 人工核验图见
`shots/combo_dispute.png`。

**这解释了历史上的「连携技连按 11 次」**：
模板在 0.51~0.65 的边缘值上乱触发。

### 3. 闪避：接上真识别

**机制（已查证）**：

| 操作 | 效果 |
|---|---|
| Shift 点一下 | **闪避**（消耗体力，能连放 2 次）|
| Shift 按住 + 方向 | 冲刺 |
| 敌人攻击瞬间闪 | 极限闪避（大量回复技力）|

**实现**：`dodge()` = 先松 Shift 再 tap
（sprint 也是 Shift 且是状态，按住时 tap 不产生按下沿）

**威胁信号**：ONNX 的三个预警标签
`EnemyAccumulatingPower` / `EnemyAttackGroundCharging` / `EnemyAttackGroundDodge`

**实测有效**：
```
[15.3s] ★ 闪避 → Shift 点一下
        ({'EnemyAttackGroundCharging': 0,
          'EnemyAccumulatingPower': 1,      ← 就是它触发的
          'EnemyAttackGroundDodge': 0}，第 1 次)
```

## 三、★ 本轮最重要的教训

### 3、4 号 bug 是**同一个错误**

> ## 把「没有数据」当成了「数据说没有」

**判据写出来之前先问三句话**：

1. **这个量在这个分支里会不会变？**
   `dist` 在「只转不走」的分支里恒为 0 —— 条件写得再对也成立不了。

2. **这个量读不到的时候，代码会当成什么？**
   `sharp` 低 → 被当成「静止」→ 误判撞墙。

3. **「没有」和「不知道」分开了吗？**
   三态写成两分支 = 有 bug。

### 方法论：**改状态机先写 20 行离线模拟**

三次翻车全部靠**离线模拟 + 读日志时间线**抓到，
**一次都不是上机试出来的**。

| 翻车 | 怎么发现 |
|---|---|
| 只转不走 → 死锁 | 读代码就看出来了 |
| 斜向门槛太慢（11 秒）| 离线模拟 20 拍暴露 |
| 超时清零进度 | 模拟打到 `acc=25→0` 的跳变 |

**比上机跑 300 秒快 1000 倍，而且能看见每一拍。**

### 另一条：**类别极端不平衡时，准确率是骗人的**

「一致率 98.8%」听起来很好 ✓ —— 但 428 帧里**只有 2 帧**真有提示 ✓
「全说没有」就有 99.5% 准确率 ✗

**该看的是**：误报率 + 漏报率 + **人工核验分歧帧**。

## 六、给下次的自己

1. **改退出条件前，先确认这个量在对应分支里会不会变**（`dist` 恒 0 那次）
2. **超时只重置计时器，不能清零进度**（`esc_run = 0.0` 那次）
3. **「没有数据」和「数据说没有」是两件事** —— 三态判定，别写两分支
4. **改状态机先写离线模拟** —— 比上机快 1000 倍
5. **类别不平衡时别看准确率** —— 看误报率 + 人工核验分歧帧
6. **验证要看「被谁调用」，不是「定义了没有」** —— `ComboUsable` 那条死代码
