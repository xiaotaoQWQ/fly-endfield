# 05 · 界面与打包

> 三个界面 + 一个 exe，以及它们各自的坑。

## 一、三个界面，各有各的用途

| 界面 | 文件 | 特点 |
|---|---|---|
| **tkinter 应用窗口** | `app_window.py` | 独立的**应用程序**（不是网页），所有参数在这里调 |
| **HTTP 调参面板** | `live_tune.py` | 浏览器打开 `127.0.0.1:8791`，同一套参数 |
| **叠加面板** | `fly_panel.py` + `overlay.py` | 半透明浮在游戏上方，**鼠标穿透** |

**为什么两个参数面板**：tkinter 是主界面（用户要求"应用程序"），
HTTP 是为了远程/手机看（也方便调试）。

> **2026-11-01 补充**：危机合约专用参数做成了 **tkinter 应用窗口里的一个区块**
> （`app_window._build_cc`，在参数区最上面），**不是网页**。
> 理由：用户要的是「本地 exe」，而 tkinter 窗口就是打包进 exe 的那个界面；
> 网页版保留成 `--cc-web`（默认关）。

## 二、★ tkinter 的线程陷阱

```
RuntimeError: Calling Tcl from different apartment
```

**Tk 必须在同一个线程里创建和 `mainloop()`。**

所以 `AppWindow.__init__` **完全不碰 tkinter**，
只在 `run()` 里（工作线程）创建 `Tk()`。

```python
class AppWindow:
    def __init__(...):
        # 只存参数，不建任何 widget ✓
        self._show_req = False    # ⚠ 必须初始化 False

    def run(self):
        self.root = tk.Tk()       # ← 在这个线程建
        ...
        self.root.mainloop()
```

**跨线程操作只走三个线程安全的标志**：

```python
request_close()   # 设 _close_req = True
request_show()    # 设 _show_req = True
# _tick() 里检查这两个标志
```

> **踩过的坑**：`_show_req` 忘了初始化 → `AttributeError`。
> 更坑的是：检查脚本**假报"已存在"**，因为它匹配到了
> `request_show()` 里的 `self._show_req = True`（赋值，不是初始化）。

## 三、★ 卡顿：`find_endfield()` 不能在非主线程调

`EnumWindows` 在 **HTTP 线程 / tkinter 线程**里会**挂住**，
而且症状每次都不一样（窗口冻结、按钮没反应、HTTP 超时）。

**对策：拆成两层**

```python
_game_probe()     # 只在主循环里跑，调 find_endfield()
_game_check()     # 只读缓存，任何线程都能调
```

`_refresh_panel_cache()`（主线程）→ `_refresh_game_cache()` → `_game_probe()`。

HTTP 的 `/api/get` 也**只读缓存** ✓ 响应从 15 秒超时变成 0.02 秒。

## 四、★ 叠加面板

### 4.1 三个必须的窗口样式

```python
WS_EX_LAYERED       # 半透明
WS_EX_TRANSPARENT   # 鼠标穿透（点不到它）
WS_EX_TOPMOST       # 永远在上面
```

**`WS_EX_TRANSPARENT` 意味着面板上的按钮点不了** ——
所以所有交互（存档、滑块、下拉框）都在 tkinter 窗口里，
叠加面板**纯显示**。

### 4.2 高度必须恒定

```python
W, H = self.w, self.h + self.extra_h    # extra_h = 战斗条 + 觅食条
```

`Overlay.update()` 尺寸不符会**抛异常**。

而叠加层的失败**绝不能杀死果蝇**：

```python
try:
    ov.update(panel.render(...))
except Exception:
    _ov_err[0] += 1        # 记数，继续跑
```

> **踩过的坑**：End 键重启"没反应" —— 其实是第二轮的第一拍
> `ov.update()` 抛异常，把整个进程杀了。

### 4.3 面板会遮住它自己要检测的东西

**「挑战成功」横幅在内容 y 250~430，而面板铺在 y 0~300 —— 正好压住。**

所以那个功能只能改用左边任务条（`mission.py`），
而 `check_occlusion` 现在也检查 `mission` 区域。

## 五、★ HTTP 面板的安全

`live_tune.py` 只监听 **`127.0.0.1`**，而且：

```python
WHITELIST = {所有合法参数名}     # 不在白名单的键直接拒绝
# 每个参数有 (lo, hi, step)，越界夹紧
```

**为什么要白名单**：`/api/set` 会 `setattr(args, key, value)`，
不加限制等于把 `args` 的写权限开放给任何能访问端口的进程。

实测：`POST attack_key=1` → `{'ok': False, 'msg': '不在白名单'}` ✓

## 六、★ 参数类型：bool / float / str 三套

| 类型 | 存哪 | 界面控件 |
|---|---|---|
| 数值 | `GROUPS`（滑块） | 滑块 |
| 布尔 | `TOGGLES`（对照组） | 复选框 |
| 字符串 | `SELECTS`（键位/角色） | 下拉框 |

**`snapshot()` 必须分别处理**，否则状态回调里 `true` 会变成 `1.0`。

**下拉框存的是"值"不是"显示文字"**：
选项写成 `(值, 显示文字)`，值是给代码用的（`attack` / `mouse_left`），
显示文字是给人看的（"攻击"）。

> 直接写显示文字的话 argparse 收到的是中文长句 ——
> **表面上不报错，但语义全丢**（`roles=("攻击", ...)` 一个都匹配不上）。

## 七、★ `ttk.Combobox` 悬停时会被滚轮改值

**这是用户真实踩到的**：

```
[键位] combo_key = q（显示为「q」）      ← 键位被静默改掉了
```

用户一边玩游戏一边滚滚轮，鼠标扫过面板 → 键位被改 ✗
→ 果蝇按 Q 但连携技是 E → 提示不消失 → 每拍都按 → 7 秒连按 11 次。

```python
cb.bind("<MouseWheel>", lambda e: "break")   # ★ 必须屏蔽
cb.bind("<Button-4>", lambda e: "break")     # Linux 上滚
cb.bind("<Button-5>", lambda e: "break")     # Linux 下滚
```

**顺手加了两件事**：
1. 面板最上面常驻一行「键位」（改错了能一眼看见）
2. 连携技连按 4 次就警告并指出当前键位

## 八、记忆存档

```python
out/memory/slot_01.npz ... slot_10.npz
```

**为什么要 10 个槽位**：做对照实验要能回到**同一个起点**。
跑一轮 → 存下来 → 关掉某个脑区再跑一轮 → 两次从同一份记忆出发，
差异才归因得到那个脑区上。

**读档只挂待办**：

```python
# 界面/HTTP 线程：
CTL["load_slot"] = n

# 主循环（自己的节拍上）：
_ls = CTL.pop("load_slot", None)
if _ls: forager["mb"].load(slot_path(_ls))
```

**绝不让别的线程直接动 `forager` 的数据结构。** 同理 `reset_mem`。

**清空记忆 ≠ 读一个空槽位**：
- `load(不存在的槽位)` → 失败，记忆原样保留
- `reset()` → 权重回到**连接组基线 `w0`**（那只什么都没学过的果蝇）

**刻意不清 `n_reward` / `n_punish`** —— 那是统计量，不属于突触状态。
清空记忆是"忘掉权重"，不是"假装没打过"。

## 九、打包成 exe

```bash
python -X utf8 build_exe.py --clean
```

### 9.1 为什么 `--onedir` 不是 `--onefile`

`--onefile` 每次启动都要把 216 MB 的 `graph/` **重新解压一遍**，
启动时间从几秒变成几十秒。

### 9.2 必须打进去的

```python
DATA_DIRS = ["graph", "templates", "tools"]
OUT_FILES = ["optic_map.feather", "vote_pairs.npz", "motor_axes.npz",
             "mb_groups.npz", "odor_pair.npz", "action_calib.json"]
# ★ 不含 fly_brain_patch.npz —— 果蝇要从零开始学
```

> 踩过：`tools/` 没打进去 → `FileNotFoundError: ...interception.dll`。

### 9.3 ★ 打包前的三道自检

```python
# ① 模板重采样自检（check_templates.py）
#    模板尺寸 vs 参考分辨率下的尺寸 vs 搜索区尺寸

# ② argparse 自检（跑 --help）
#    ★ 必须跑 endfield_fly.py，不是 fly_app.py
#    （fly_app 会先请求提权，--help 根本到不了 argparse ——
#      第一版自检"通过"了，但输出只有 34 字节，等于没测）
#    ★ 还要有长度下限（< 2000 字节就报错）

# ③ 多分辨率检查（check_resolutions.py）
#    951 帧 × 8 种分辨率
```

### 9.4 ★ argparse 的 help 里不能有裸 `%`

```python
ValueError: unsupported format character '?' (0xff0c)
```

argparse 会对 help 做一次 `help % params` ——
字符串里裸的 `%` 会被当成格式符。

**这个 bug 只在 exe 上暴露**（源码跑没走到那条路径），用户双击才看到崩。

### 9.5 ★ 中文和编码

| 问题 | 对策 |
|---|---|
| `.cmd` 里有中文 | **纯 ASCII**。`chcp 65001` 救不了（ANSI 代码页会撕碎非 ASCII 字节）|
| exe 里 print 中文崩 | `reconfigure(errors="replace")` + `SetConsoleOutputCP(65001)` |
| 日志文件 | Tee 到 `<exe目录>\fly_app.log` |
| 免责声明乱码 | 写成 `utf-8-sig`（带 BOM），记事本才认 |

**一个 `UnicodeEncodeError` 就能杀死整只果蝇。**

### 9.6 提权

```python
ShellExecuteW(None, "runas", sys.executable,
              list2cmdline(sys.argv[1:]), ...)   # ★ 是 argv[1:]，不是 argv
```

> 踩过：传了 `argv` → 多一个位置参数 → argparse 报错 →
> **用户点了 UAC 之后什么也没发生**。

### 9.7 发布前清垃圾

```python
# build_exe.py 里
for _junk in ("fly_app.log", "out"):
    # 删掉 —— 否则用户拿到一个带着别人运行记录的包
```

### 9.8 免责声明每次打包自动刷进发布目录

`build_exe.py` 从 `NOTICE.txt` 读，写成 `免责声明与使用须知.txt`（utf-8-sig）。
