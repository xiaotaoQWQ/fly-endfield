# 04 · 输入与执行

> 按键怎么送进游戏，以及为什么这么麻烦。

---

## 一、★ 两条注入路径，游戏只认一条

| 方式 | 实现 | 终末地里 |
|---|---|---|
| `SendInput`（Win32 标准 API）| `input_sim.py` / `win_click.py` | **键盘不生效** / 鼠标可用 |
| **Interception**（过滤驱动）| `interception_py.py` | **键盘生效** |

### 实测现象

```
SendInput(W) 返回 1（声称成功）
但 GetAsyncKeyState(W) = 0x0000（系统键盘状态毫无变化）
```

**这不是"检测到作弊"，而是"这类事件根本不走那条路"**：
ACE（内核级反作弊驱动）在内核里区分硬件路径和 `SendInput` 路径，
后者不落地。

> ⚠ **说清楚 Interception 是什么**：它是一个**开源的键盘/鼠标过滤驱动**
> （LGPL-3.0），KVM 软件、无障碍工具、远程桌面都在用它。
> 它**没有**修改游戏、**没有**读内存、**没有**欺骗任何检测逻辑。
> 它做的只是把按键事件送进**驱动栈**，而不是送进应用层——
> 这是键盘输入本来就存在的两条合法路径之一。
>
> 换成它的原因很朴素：另一条路在这个游戏里不落地，仅此而已。

### 什么时候用哪个

```python
# 键盘（移动、技能、大招、连携技）→ Interception
ex.combat_press("1")
ex.combat_hold_down("2")

# 鼠标（普攻默认 mouse_left）→ SendInput
#   Interception 也能发鼠标，但 SendInput 在鼠标上实测可用，
#   而且不用管理员权限就能跑通鼠标部分（调试时方便）
```

**发送键盘输入必须管理员权限。**

### 驱动安装

```bash
# 管理员
tools/Interception/Interception/command line installer/install-interception.exe /install
# 卸载
install-interception.exe /uninstall    # + 重启
```

**设备号分段**（踩过的坑）：

```
键盘 1–10
鼠标 11–20
```

按 `1..10` 去查鼠标设备**永远返回空**。

## 二、★ 长按：必须拆到不同拍

```python
# ✗ 错的 —— 会卡死整个主循环
ex.combat_press(key)
time.sleep(1.0)

# ✓ 对的 —— 按下记时刻，到点再松
ex.combat_hold_down(key)
ctx["hold_until"] = ts + 1.0
# ... 下一拍 ...
if ctx["holding"] and ts >= ctx["hold_until"]:
    ex.combat_hold_up(key)
```

**为什么**：`--attack-hold` 默认 **1.0 秒**，而决策拍是 **400 ms**。
在拍内 `sleep` 会让**走路、挨打判定、连携技**全部卡住 1 秒。
战斗里 1 秒足够让血量掉一截、让连携技提示出现又消失。

**哪些是长按**：
- 普攻（`--attack-hold`）—— 因为是长按鼠标才能出连击
- 大招（`--ult-hold`）—— 长按同一个键放那个角色的专属大招
- 技能（点按，不用跨拍）

## 三、键位映射

```bash
--attack-key  mouse_left      # 普攻（鼠标或键盘）
--combo-key   e               # 连携技（choices: e/q/f/r）
--key-ult     1,2,3,4         # 大招键序列（轮换）
--key-skill1..4 1,2,3,4       # 四个技能槽各按哪个键
--role-1..4    weaken/buff/heal/none   # 四个槽各是什么含义
```

**技能槽和键是两件事，独立配**：
换配队只改键，换打法只改含义。

### ★ 大招为什么轮换

**长按同一个键放的是那个角色的专属大招，每个角色各自有冷却。**
果蝇看不出谁好了，所以轮换：

```python
_ULT_KEYS = tuple(k.strip() for k in args.key_ult.split(","))
_uk = _ULT_KEYS[fod["n_ult"] % len(_ULT_KEYS)]
fod["n_ult"] += 1
```

默认 `--ult-cool 20` 秒，四个角色轮一圈 80 秒，
比一般大招冷却长，转到谁基本都能放出来。

### ★ 连携技没有冷却

`--combo-cool` 默认 **0**（用户明确要求"有就可以放"）。

**但这就意味着按错键时的症状是"每拍都按、永远不生效"**：
提示不消失 → 检测器一直为真 → 一直按。

所以加了诊断：连续按满 4 次且间隔都很短时，警告一次并指出当前用的什么键。

## 四、运动解码

### 群体解码口径（`--motor pop`，默认）

```python
pm = dec.step(r)     # motor_decode.py
# pm["key_w"], pm["key_s"], pm["key_a"], pm["key_d"]
# pm["turn_dx"]      ← 转身像素
# pm["z"]["thrust"/"strafe"/"turn"]   ← 三条轴
```

三条轴直接驱动：

| 轴 | 阈值 | 动作 |
|---|---|---|
| 推力 `thrust` | `--pop-thr-w` = -0.50 | 高于它按 W |
| 横移 `strafe` | `--pop-thr-strafe` = 0.80 | 超阈值按 A/D |
| 转身 `turn` | — | 转鼠标 |

**推力轴默认"自锁"** —— 约 70% 的时间都在走。
这是刻意的：站着不动的果蝇不会走到任何地方，而"能走到某个地方"是第二条底线。

### 旧口径（点名的 5 对左右 DN 取差）

`--motor dn`。已经不用了，留着做回归对比。

## 五、撞墙反射

```
条件：速度 < 某阈值 且 持续 --stuck-sec 秒
动作：松开所有移动键，原地转
```

**进战斗（红叉亮）时不触发** —— 用户明确要求。
战斗中原地转是自杀行为。

`--escape-grace`（默认 10 秒）：开局这段时间不触发，
避免一进游戏就被误判成卡住。

## 六、★ 执行器的"单一闸门"

对照组的「运动输出关掉」不是在每个调用点加 `if`，而是**包一层空操作**：

```python
if not args.ab_motor:
    ex = _NoMotor(ex)      # 拦截发送类方法，其余透传
```

**为什么**：调用点有 10 来个，漏一个就白测了。

**然后第一版真的漏了**：

```python
if name.startswith(("apply", "press", "hold", "click")):   # ✗
```

漏了 **`combat_press`** 和 **`combat_hold_down`** ——
那才是打怪真正用的通道。结果"关掉运动输出"之后它照样在打。

```python
_SEND = ("apply", "press", "hold", "click", "combat_")     # ✓
```

`release_*` 是**刻意放行**的：松键永远安全，卡着不放更糟。

> **教训：「关掉某个功能」要实现成「单一闸门」，而不是「在每个出口加判断」。**
> 前者漏了只有一个地方要改，后者漏了你根本不知道漏了。
>
> 这次是靠 `re.findall(r'\bex\.(\w+)\(', src)` 把方法名**列全**才发现漏的。

## 七、常见故障对照

| 症状 | 先查 |
|---|---|
| 游戏里一个键都不按 | 是不是管理员权限 / Interception 装没装 |
| 按了但游戏没反应 | 键位和游戏里对不上（面板最上面那行「键位」）|
| 长按变成点按 | `--attack-key` 是键盘键 → 退回点击（键盘没有长按）|
| 卡住不放 | 长按的"抬起"那一拍没执行到（检查是否跨了暂停）|
| 鼠标乱点 | `win_click.py` 的坐标是**屏幕坐标**，不是窗口坐标 |
