# 06 · 踩坑总表

> **按症状查，不按原因查。** 因为下次你是先看到症状，才来查的。
>
> 格式：`症状` → 原因 → 修法。

### ★ 场景「不是撞墙却一直报撞墙」/「站着原地转圈」

先看 tick 日志里有没有 `!` 标记（测速不可信）：
- **`!` 很多** → `MapOdometry` 的 `sharp` 阈值太严。小地图**在转头时会旋转**，
  而 `phase_shift` 是**纯平移**相关 → 只要在转就必然测不准 →
  「测不准」被当成「没在动」→ 误判撞墙。
  阈值在 `ef_vision.py` 的 `self.trust = sharp >= 1.0`。
- **`!` 很少但还报** → `min_speed`（默认 1.5 地图像素/秒）太高。
  实测走速约 7，所以 1.5 是准的；如果地图缩放变了要重调。
- **站着原地转** → 逃逸分支只 `apply_raw(turn_dx=...)` 没按移动键，
  位移恒为 0，于是「累计位移够了才退出」永远不成立 → 无限转。
  修法见 `endfield_fly.py` 的逃逸段：必须**边转边走 + 斜向 + 超时反向**。

**根因一句话**：**「没有数据」和「数据说没有」是两件事。**

## A. 程序起不来 / 直接崩

### A1. 双击 exe 报 `ValueError: unsupported format character '?'`

**原因**：argparse 的 `help=` 字符串里有**裸的 `%`**。
argparse 会对 help 做一次 `help % params`，`%（` 不是合法格式符。

**关键**：这个 bug **只在 exe 上暴露**（源码跑没走那条路径）。

**修法**：help 里写 `%%`，或者干脆用「百分之」把 `%` 去掉。
**并且**在 `build_exe.py` 里加一道 `--help` 自检。

---

### A2. `AttributeError: 'AppWindow' object has no attribute '_show_req'`

**原因**：`__init__` 里忘了初始化。

**坑上坑**：检查脚本**假报"已存在"**——它匹配到了
`request_show()` 里的 `self._show_req = True`（赋值，不是初始化）。

**修法**：`__init__` 里 `self._show_req = False`。

---

### A3. `ModuleNotFoundError: No module named 'unittest'`

**原因**：`build_exe.py` 里加了 `--exclude-module unittest`。

**链路**：`scipy.sparse → scipy._lib._array_api → numpy.testing` 需要它。

**修法**：去掉这个排除。

---

### A4. `FileNotFoundError: ..._internal\tools\Interception\...\interception.dll`

**原因**：`tools/` 没加进 `DATA_DIRS`。

**修法**：`DATA_DIRS = ["graph", "templates", "tools"]`。

---

### A5. `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'`

**原因**：exe 里没有 `-X utf8`，一个 `print` 就杀死整只果蝇。

**修法**：`reconfigure(errors="replace")` + `SetConsoleOutputCP(65001)`。

**坑上坑**：补丁插到了 `import sys` **之前** → `NameError`。
必须在 import 之后。

---

### A6. `SyntaxError: no binding for nonlocal 'ok' found`

**原因**：在模块级脚本里用了 `nonlocal`。

**修法**：用列表当可变闭包（`state = [True]`）。

---

### A7. 点了 UAC 之后什么也没发生

**原因**：提权时传的是 `sys.argv` 而不是 `sys.argv[1:]`
→ 多一个位置参数 → argparse 报错 → 进程直接退出。

**修法**：`list2cmdline(sys.argv[1:])`。

---

### A8. `.cmd` 里中文变成乱码 / 命令被撕碎

**原因**：ANSI 代码页会撕碎非 ASCII 字节。`chcp 65001` **救不了**。

**修法**：`.cmd` 文件**纯 ASCII**。

---

## B. 游戏里没反应（算了但不动作）

### B1. 果蝇算得很欢，游戏里一个键都不按

**原因**：**没有管理员权限**。Interception 驱动发不出键。

**修法**：双击 exe → UAC 点「是」。

**验证**：看日志里有没有 `Interception：键盘 N，鼠标 M` 那行。

---

### B2. 键盘没反应，但鼠标能动

**原因**：`SendInput` 的键盘事件被 ACE 丢弃（鼠标不丢）。

**修法**：键盘必须走 Interception（见 04 篇）。

---

### B3. 某个功能永远不触发，而且不报错

**★ 最常见、最难查的一个。**

**原因**：抓屏抓的是**屏幕**，有窗口压在上面。
而且**不报错、不崩溃、只是那个功能永远不触发**。

**典型症状对照**：

| 被挡的区域 | 症状 |
|---|---|
| 连携技搜索区 | E 键永远检测不到 → 永远不放连携技 |
| 血条 | 血量读不到 → 自动挨打失效、大招永远不放 |
| 任务完成 | 打完副本不给奖励 |

**三个症状看起来毫不相关，根因是同一个。**

**修法**：看启动时的**遮挡警告**（`check_occlusion`），把窗口挪开。

---

### B4. 键位莫名其妙变了

**原因**：`ttk.Combobox` **悬停时会被鼠标滚轮改值**。
用一边玩游戏一边滚滚轮，鼠标扫过面板 → 键位被静默改掉。

**实测**：`combo_key` 被改成 `q` → 连携技永远按错键 →
提示不消失 → **每拍都按** → 7 秒连按 11 次。

**修法**：`cb.bind("<MouseWheel>", lambda e: "break")` +
面板常驻一行「键位」+ 连按 4 次就警告。

---

### B5. 长按变成点按

**原因**：`--attack-key` 是键盘键。Interception 的 tap 本身有沿，
键盘键没法长按。

**修法**：要长按就把 `--attack-key` 改成 `mouse_left`。

---

## C. 屏幕读取 / 检测

### C1. 相关值是个天文数字（如 `+744011840`）

**原因**：**零方差没防住**。
归一化相关 = `num / (std(x)·std(t))`，平坦区域（纯色/黑屏/对话框白底）
让 `std(x)≈0` → 分母被 `1e-6` 兜住 → 爆炸 → 判定为"匹配"。

**修法**：
```python
den = np.sqrt(var) * tn
sc = np.where(den > 1e-3, num / np.maximum(den, 1e-6), 0.0)
```

---

### C2. 相关值永远 0，而且不报错

**原因**：**模板比搜索区还大** → 撞上 `if g.shape[0] < th: return False`。

**典型触发**：`TEMPLATES` 里的参考分辨率写错，重采样把模板放大了。

**修法**：对一下「模板尺寸 / 参考分辨率 / 搜索区尺寸」三者关系
（`check_templates.py` 就是干这个的）。

---

### C3. 一半的帧都误判为"有提示"

**原因**：**搜索区太大**，噪声底太高。

**实测**：

| 搜索区 | 噪声底 | `>=0.45` 的帧数 |
|---|---:|---:|
| `(1400,590) 200×100` | +0.333 | 10 |
| `(1240,400) 700×560` | **+0.437** | **75** ✗ |

**修法**：收紧搜索区。**区域不是越大越好。**

---

### C4. 换了分辨率就认不出来

**原因**：`TEMPLATES` 里的参考分辨率写错，或者模板没跟着重采样。

**修法**：`prof.template(name)` 会按当前分辨率等比缩放。
**注意缩的是"分辨率比例"，不是"缩到搜索区大小"**（那会拉伸变形）。

---

### C5. 所有区域都整体偏移几十像素

**原因**：**内容区（去掉黑边）测错了**。

**踩过的三次**：

| 方法 | 结果 |
|---|---|
| 取中间一条线 | 副本里得到 `(115,80) 2445×1440` → 全部偏 +111 px ✗ |
| 取 5 条线中位数 | 窗口压住黑边时得到 `(0,38) 2560×1482` ✗ |
| **每行纯黑比例 + 对称性检查** | `(0,80) 2560×1440`，6/6 和 8/8 稳定 ✓ |

**修法**：用纯黑比例 + 对称性检查，不对称就退回 16:9 公式。

---

### C6. `mean(axis=(1,2))` 得到 1 个数

**原因**：`grab(w, 1)` 返回 `(1,w,3)`，`mean(axis=(1,2))` 会把它压成标量。

**修法**：reshape 成 `(n,3)` 再 `mean(axis=1)`。

**症状**：测量**静默地**退回了公式值 —— 因为它没抛异常。

---

### C7. 颜色判据在录像上零误报，实机误判

**原因**：颜色判据对**区域**极其敏感 ——
区域里任何同色东西（伤害数字、拾取高亮、buff 图标）都能凑够占比。

**修法**：
1. **区域要切到目标本身**（先逐行定位像素在哪，别用一大块）
2. **至少两个正交条件**（占比 + 横向跨度），别只数面积
3. 测**反向样本**：想清楚"还有什么东西长得像它"，专门造那个测

**什么时候放弃**：三版判据都在录像上零误报、实机上都误触 →
说明"用屏幕判断游戏状态"这条路本身不可靠 → **关掉它，别再打补丁**。

---

### C8. 用"最长连续段"判横带，判不出来

**原因**：任务条上有文字和图标，金色是**断开**的，最长段只有 25% 宽；
而一个 60 px 宽的实心金块反而有 15%。

**修法**：用**横向跨度**（最左到最右），不用连续长度。

---

### C9. 算"噪声上界"算出一个很高的值

**原因**：**真值集合不完整**。录制里完成状态持续了两帧，只排除了第一帧，
把第二帧真值当成噪声了。

**后果**：为了躲开"噪声"，把阈值抬到一个错的高度。

**修法**：算噪声上界之前，**先确认真值集合完整**。

---

## D. 脑 / 学习

### D1. 网络静默，`|r|` 恒为 0

**原因**：**零基线的驱动**。气味/视觉注入如果基线是 0，
网络会被完全压住。

**修法**：注入要**持续不脉冲** + **要有基线活动**。

---

### D2. 学习看起来没生效（权重在漂但行为不变）

**原因**：读了 `r[mbon].mean()`（MBON 神经元自己的活动）而不是
`w @ r[kc]`（网络投给 MBON 的输入）。

后者才是"学了多少"的真实反映。

---

### D3. 31 次技能里 30 次都是主攻

**原因**：轮换阶段的先天优先级给的是 1.00/0.90，
**比主攻还低或持平** → 主攻天生压过轮换 → 轮换等于没发生。

**修法**：给 **1.45**（明显高于主攻上限 `1.0 + 学习偏移 0.30 = 1.30`）。

---

### D4. 血 25% 了但不回血

**原因**：学习偏移**没有上界** —— 组 0 被强化后偏移到 0.92，
盖掉了保命规则的先天差距（只有 0.14）。

**修法**：`p + learn_gain * np.tanh(g / (2*spread))`，夹进 ±learn_gain。

---

### D5. "回血"和"格挡"永远学不出来

**原因**：**这是信号问题，不是算法问题**。
果蝇从画面上看不出技能是干什么的（没有 mod）。
"没挨打"不是信号，"后续打得动"也不是信号。

**修法**：技能语义必须当**本能**写死（`innate_priority`），
学习只在上面微调。

---

### D6. 战况明明很好，但它一直不放大招

**原因**：**血条读不到**（被窗口挡住）→ 血条不可读就不放大招。

**修法**：看遮挡警告。

---

## E. 主循环 / 稳定性

### E1. 按 End 暂停后"卡住了"，或者重启"没反应"

**真相**：不是卡住。是**第二轮的第一拍 `ov.update()` 抛异常**，
把整个进程杀了。

**修法**：
```python
try:
    ov.update(panel.render(...))
except Exception:
    _ov_err[0] += 1        # 叠加层失败绝不能杀死果蝇
```

---

### E2. End 键"要的是暂停不是停止"

**原因**：原来的实现是 `break` 出循环 → 整轮结束，`t0` 重置。

**修法**：按下 End 后 `CTL["running"] = False` 但**不 break**，
落到暂停分支（松键、隐藏叠加层、`continue`）——
**`t0`、轨迹、计数、饥饿值全部保留**。

---

### E3. HTTP `/api/get` 超时 15 秒，线程堆到 82 个

**原因**：`find_endfield()`（`EnumWindows`）在 **HTTP 线程**里会挂住。

**修法**：拆成 `_game_probe()`（只在主循环跑）和 `_game_check()`（只读缓存）。
响应从 15 秒变 0.02 秒。

**同样的问题在 tkinter 线程也发生过**（窗口冻结、按钮没反应）。

---

### E4. 长按把整个主循环卡住 1 秒

**原因**：拍内 `time.sleep(1.0)`。而决策拍只有 400 ms。

**后果**：走路、挨打判定、连携技全部卡住 1 秒。

**修法**：按下/抬起拆到**不同拍**（见 04 篇）。

---

### E5. 战斗中原地转圈

**原因**：撞墙反射在战斗中触发了。

**修法**：进战斗（红叉亮）时不触发撞墙反射。

---

## F. 打包 / 发布

### F1. 打包前自检"通过"了，但根本没测到东西

**原因**：自检跑的是 `fly_app.py` —— 它会先请求提权，
`--help` 根本到不了 argparse。

**表现**：自检"通过"，但输出只有 **34 字节**（那是"正在请求管理员权限"）。

**修法**：自检跑 `endfield_fly.py`，**并且加输出长度下限**（< 2000 字节就报错）。

---

### F2. 发布包里带着别人的运行日志

**原因**：`fly_app.log` 是运行产物，打包时没清。

**修法**：`build_exe.py` 里 `for _junk in ("fly_app.log", "out")` 删掉。

---

### F3. GitHub 上 `git add .` 会推 90 GB

**原因**：仓库根目录里混着**游戏本体安装目录**（90 GB）。

**修法**：`.gitignore` 逐条排除。推之前**先跑 `git status --porcelain` 看清单**。

---

### F4. GitHub 显示 `许可: NOASSERTION`

**原因**：`LICENSE` 里是**说明性的文字**（讲本项目用什么许可 + 列第三方），
不是许可的**完整正文**。

**修法**：`LICENSE` 放完整正文（AGPL-3.0 全文），
第三方说明单独放 `THIRD-PARTY.md`。

## G. 工程习惯（这一类不是 bug，但会反复害人）

### G1. ★ 多步补丁的守卫写错，导致定义没插、调用插了

```python
if old_text in src and 'new_symbol' not in src:   # ✗
    src = src.replace(old_text, new_text)
```

**三次都是**：同一次补丁的**前一步**刚把 `new_symbol` 插进去，
于是后一步的守卫判定为"已经有了"、整块没插 ——
**定义没插、用它的地方插了** → 启动 `NameError`。

具体三次：
1. `_tick_keys` 定义被 `keys=list(_tick_keys)` 挡掉
2. `_mem_menu` 方法被按钮里的 `self._mem_menu(n)` 挡掉
3. `start_app` 的 `mem` 参数被 `AppWindow.__init__` 的同名参数挡掉

**教训**：守卫要看**整个补丁执行完的最终状态**，不能一步一看。
更稳的做法：每步用**互不重叠的锚点**，或者干脆用编辑工具逐处改。

---

### G2. ★ PowerShell 里的 `\"` 会把引号吃掉

**症状**：`["attack","buff"]` 变成 `[attack,buff]` → `NameError`。

**修法**：**别在 PowerShell 里写带引号的 Python 代码**。
写成 `.py` 文件再 `python 文件.py`，或者用编辑工具。

---

### G3. ★ 自检报错时，先怀疑自检本身

踩过 N 次：

- 合成帧里 `rng.integers` 被调了两次 → "显示"帧里是另一串噪声 → 自检全红
- 循环只喂了 9 拍（3.6 秒 < 4 秒）→ 看起来像"计时不工作"
- 模板缩放算错 → 相关值只有 0.33 → 看起来像"认不出来"

**自检的 bug 比被测代码的 bug 更容易骗人。**

---

### G4. ★ 标定必须"离线回放验证"，不能只看"当时抓到了"

**不是**"我采到模板的时候它匹配得很好"，
而是"在**一整段真实录像**上，信号和噪声之间有一条清晰的沟"。

```
录屏 → 离线跑全部帧 → 看分布（中位数=噪声底，最高=真信号）→ 确认有沟
```

---

### G5. ★ 什么时候该停止打补丁

**当你连续两三次"修好了但实机又坏了"，就该问：
是不是这个方案本身有个我绕不过去的假设？**

而不是再想一个更聪明的阈值。

任务完成检测就是例子：三版判据都在录像上零误报、实机上都误触 →
假设「屏幕上的某个画面 == 某个游戏状态」在"副本结束"这个事件上**不成立**
（状态空间太大：不同副本、不同结算动画、不同 UI 层级、中途切镜头）。

**假设不成立的地方，再好的判据都是在赌。**
