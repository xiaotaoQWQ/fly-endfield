## 一、一拍里发生什么（主循环 tick）

主循环在 `endfield_fly.py`，默认 **2.5 Hz**（`--hz`）。一拍大约 400 ms。

```
① 抓一帧整屏                     lf.update()            ~87 ms
   ├─ 红环（战斗标记）            cmark.step(lf.at(...))
   ├─ 撤离面板（副本内？）        emark.step(lf.at(...))
   ├─ 连携技徽标（能放E？）       kmark.step(lf.at(...))
   └─ 小地图切片                  lf.at(rect_disc...)

② 眼睛（30 Hz 独立线程，更快）    eye_th.read() → drive
   └─ 对比度太低 → 自动切回小地图口径（滞回）

③ 气味 + 饥饿                     forager["enc"].write(...)
                                  forager["hg"].step(dt)

④ 神经网络（10 内步）             r ← 0.5·r + tanh(W·r + drive)
                                  + 蘑菇体贡献 mb.contribution(r)

⑤ 解码
   ├─ 群体解码三条轴（推力/横移/转身）    dec.step(r)
   ├─ 动作通道（前进/转/跳/冲）          amap.step(r)
   └─ MB 分区（4 组 → 技能）              mb.group_scores(r)

⑥ 决策
   ├─ 觅食驱动 = (先天 + 学习) × 饥饿增益  → 超阈值就出手
   └─ 先天优先级 + 学习微调 → 选技能槽

⑦ 执行                          ex.apply_raw(...) / ex.combat_press(...)
   └─ 长按拆成两拍（按下记时刻，到点再松）

⑧ 记录                          logbuf / 状态回调 / 录像
```

**关键点：① 里所有 HUD 都从**同一帧**切出来。**
改之前是 7 次独立抓屏，两次之间隔十几毫秒——而游戏是 60 fps 在跑的，
"血条还剩 30%"和"红环亮着"可能不是同一时刻的状态。

## 二、模块分层

```
                     ┌──────────────────────────────┐
   用户界面           │ app_window.py  (tkinter 窗口) │
                     │ live_tune.py   (HTTP 面板)    │
                     │ fly_panel.py   (叠加渲染)     │
                     │ overlay.py     (分层窗口)     │
                     └──────────┬───────────────────┘
                                │ 写 args.* / CTL[...]
                     ┌──────────▼───────────────────┐
   主循环             │ endfield_fly.py               │
                     └──┬────┬────┬────┬────┬───────┘
        ┌───────────────┘    │    │    │    └──────────────┐
        ▼                    ▼    ▼    ▼                   ▼
   screen_profile.py    ef_eye  mb_learn  motor_decode   combat.py
   live_frame.py        retina  odor_map  action_map     mission.py
   ef_shot.py                   (脑)      motor.py       (视觉检测)
   (屏幕读取)                    │         │
                                │         ▼
                                │      input_sim.py
                                │      interception_py.py
                                │      win_click.py
                                └──► (执行)
```

**分层的意义**：
- 上层（界面）只改 `args` 和 `CTL`，**不直接动主循环的数据结构**
- 主循环只读 `args`，**不回调界面**
- 唯一例外：读档要换蘑菇体权重 → 界面只写 `CTL["load_slot"]`，
  主循环在**自己的节拍上**执行（见 05 篇）

## 三、控制流：启动与暂停

```python
CTL = {"running": not args.panel,   # 面板模式下等待点击「启动」
       "pause": False,              # End 键 = 暂停（原地）
       "stop": False,               # 「停止」= 真退出
       "load_slot": None,           # 读档请求（主循环执行）
       "reset_mem": False}          # 清空记忆请求
```

**End 键 = 暂停，不是停止**：
按下 End 后 `CTL["running"] = False`，但**不 break**——
落到暂停分支，松键、隐藏叠加层、`continue`。
**这样 `t0`、轨迹、计数、饥饿值全部保留**，点「启动」能接着跑。

**外层的 `while True:` 是"轮"**，不是"拍"。一轮跑完（到 `--seconds`）
会重新开始，但记忆（蘑菇体）保留。

## 四、分辨率适配层（最重要的一层）

`screen_profile.py` 干三件事：

### ① 测出"内容区"（去掉黑边）

```
measure_content_rect(grab_fn) -> (x, y, w, h)
```

方法：**逐行/逐列的纯黑像素比例** + **对称性检查**。
- 黑边是纯黑（RGB 全 0），比例高
- 游戏画面（3D 渲染）不可能整行全黑
- **对称性检查**：上下黑边应该差不多、左右应该差不多
  不对称 → 说明测错了（比如有窗口压在黑边上）→ 退回 16:9 公式

> 为什么不用"中间一条线"：实测在副本里取单线得到 `(115,80) 2445×1440`，
> 所有区域整体偏移 111 px ✗ 改用 5 条线取中位数还是会被窗口干扰 ✗
> 最后是"每行纯黑比例 + 对称性"才稳。

### ② 归一化坐标

```python
REGIONS = {
    "marker":  (28/2560,  47/1440,  48/2560,  50/1440),   # 左上红环
    "evac":    (24/2560,  45/1440, 213/2560,  53/1440),   # 撤离面板
    "hp":      (1060/2560, 1324/1440, 441/2560, 12/1440), # 主血条
    "combo":   (1400/2560, 590/1440, 200/2560, 100/1440), # 连携技徽标
    "mission": (100/2560, 410/1440, 300/2560, 70/1440),   # 任务条文字
    ...
}
```

`prof.rect(name)` 返回**当前分辨率下的内容坐标**。
所有检测器都只认这个，**没有任何硬编码的像素坐标**。

### ③ 模板重采样

```python
TEMPLATES = {
    "evac_panel": (2560, 1440),   # 这个模板是从 2560×1440 截的
    "combo_e":    (2560, 1440),
    "kill_text":  (2560, 1440),
}
```

`prof.template(name)` 按当前分辨率**等比缩放**模板。
不缩放的话归一化相关会整体偏低、认不出来。

> ⚠ 踩过的坑：模板的"参考分辨率"写错，会放大成比搜索区还大，
> 撞上 `if g.shape[0] < th: return False` 的防线 → **永远返回 False，而且一声不吭**。

### ④ 遮挡检查

```python
check_occlusion(hwnd, prof) -> dict{区域名: 窗口标题}
```

取每个区域**中心点**，`WindowFromPoint` 看最上层窗口是不是游戏自己。

**为什么必须有**：抓屏是抓屏幕，任何压在上面的窗口都会被当成游戏画面读进去，
**不报错、不崩溃、只是那个功能永远不触发**。

## 五、两个"眼睛"（口径切换）

| 口径 | 输入 | 优点 | 缺点 |
|---|---|---|---|
| `--eye main`（默认） | 主画面（第一人称/第三人称） | 感光细胞方位角直接对应画面横向位置 | 相机贴背时会失效 |
| `--eye minimap` | 小地图俯视 | 一直有信息 | 方位角要靠 heading 换算 |

`--eye-auto` 会在对比度太低（`--eye-contrast`）时**滞回切回**小地图口径，
回到 `--eye-back` 以上且持续 4 拍才切回主画面，两次切换至少隔 `--eye-dwell` 拍。

> 为什么要滞回 + 最小驻留：实测不加的话 120 秒里抖了 12 次（约 10 秒一次），
> 两种感官的统计特性完全不同，频繁换眼睛对网络不友好。

## 六、性能预算（2.5 Hz = 400 ms/拍）

| 项 | 耗时 | 备注 |
|---|---:|---|
| 整屏抓取 2560×1440 | ~87 ms | 每拍一次 |
| 单个小区域抓取 | ~15 ms | 固定开销占大头，**跟区域大小几乎无关** |
| 神经网络 10 内步 | 取决于稀疏度 | `args.sparse` 控制 |
| 眼睛线程 | 30 Hz 独立 | 不占主循环 |

**所以：能用同一帧切片的，就不要单独抓。**
7 个区域分开抓 = 105 ms；整屏一次 = 87 ms，**还更一致**。
