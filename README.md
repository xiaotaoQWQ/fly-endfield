# 果蝇全脑驾驶终末地

> 用一只真实果蝇的**全脑连接组**（211,577 个神经元 · 26,028,386 个化学突触），
> 去驾驶《明日方舟：终末地》里的角色。

**这不是"AI 打游戏"，是一个行为艺术作品。**

复眼感光细胞接收画面光流，211,577 个神经元按真实突触权重互相激发，
多巴胺在打死和挨打时改变蘑菇体的连接。趋光、避碰、卡住反射、技能轮换 ——
都不是 if-else，是从网络动力学里**长出来的**。

但它**不理解游戏**。它看到的是几个数字：一个布尔说"有敌人"，
一个标量说"疼"。是作者理解了游戏，再把理解翻译成这几个数字喂给它。

> **这个作品想说的是：「理解」这件事，一半在脑里，一半在世界给它的接口上。**
> **你把接口定义成什么，它就"理解"什么。**

## 它真的在控制那个角色吗？

这是这个项目**唯一重要的技术问题**。别听我说，自己验证：

**面板上有一个「对照组（消融实验）」区域，里面第一个开关是「连接组（真实神经元）」。**

把那个勾去掉 —— 神经网络输出会被替换成**随机数**，
其余一切不变（照样读屏幕、照样按键、照样走路）。

> **如果关掉前后行为差不多，那这两亿个突触就只是装饰。**
> **那时候这个项目的前提就不成立。**

同一组开关还有：多巴胺（关掉=学不会）、蘑菇体学习（关掉=权重冻结）、
视觉、气味、饥饿、运动输出。每个都能单独消融。

测出来的结果（关掉连接组后的行为差异）见 `DECISIONS.md`。

## 它到底"理解"了什么

**它不理解游戏。** 准确的说法是：

```
       《终末地》                    果蝇的脑
    （真实的游戏世界）            （211,577 个真神经元）
            │                              │
            └──────► 我写的翻译层 ◄────────┘
                    ↑
              语义全在这里
```

果蝇的复眼和嗅觉神经元收到的**不是游戏画面**，是几个数字：

| 我说的 | 实际喂进去的 |
|---|---|
| 「它看到敌人」 | 一个**布尔值**：左上角红环亮不亮 |
| 「它闻到气味」 | **就那一个布尔**（连梯度都没有） |
| 「它挨打了」 | 血条少了一截 → 一个标量 |
| 「它用技能」 | 蘑菇体 4 个分区的输出 → 查表映射到键 1~4 |

**「红环」不是气味。「技能 3 是增伤」也是我写的，不是它学出来的。**

它能理解的是**那几个数字之间的关系**，不是游戏。
换个界面它立刻变瞎 —— 这一点开发过程中已经反复验证过。

> **这个作品想说的是：「理解」这件事，一半在脑里，一半在世界给它的接口上。**
> **你把接口定义成什么，它就"理解"什么。**
> **果蝇的脑是真的，游戏是真的，中间那层翻译是我写的 —— 而那一层，才是这个作品。**

## 它做了什么

| 系统 | 实现 |
|---|---|
| **感觉** | 复眼感光细胞 ← 画面光流（分区投射，含 FOV 几何）|
| **嗅觉** | ORN（按肾小球命名）← 屏幕上的"敌人"信号 |
| **脑** | MaleCNS 全中枢神经系统，速率模型 `r ← 0.5r + tanh(W·r + drive)`，10 内步/拍，2.5 Hz |
| **情绪** | 多巴胺 ← 打死/挨打。三因子规则 `Δw = η·DA·relu(x_pre − θ)`，只改 KC→MBON |
| **学习** | 蘑菇体 4 个分区（按 DAN→MBON 行剖面 k-means），分区输出 → 选技能 |
| **本能** | 技能语义（攻击/增伤/格挡/回血/聚怪）当**先天**写进去，学习只在上面微调 |
| **饥饿** | 内稳态：越打越饿，打死才饱。饿 → 阈值降低 → 更凶 |
| **运动** | 下行神经元群体解码 → WASD + 鼠标 + 技能键 |

细节见 [`DECISIONS.md`](DECISIONS.md)（**3700+ 行**，记录了每个决策和踩过的坑）。

## 快速开始

### 1. 环境

- Windows 10/11
- Python 3.11+（开发用 3.14）
- **管理员权限**（键盘注入用 Interception 驱动，没有权限完全不生效）

```bash
pip install numpy scipy pandas pyarrow pillow matplotlib
```

### 2. 拿到连接组数据

**仓库里不含脑数据**（1 GB）。去 Janelia 下载：

```
https://www.janelia.org/project-team/flyem
```

需要这几个文件（放进 `data/`）：

```
data/connectome-weights-male-cns-v1.0-minconf-0.5.feather      (~1.0 GB)
data/body-annotations-male-cns-v1.0-minconf-0.5.feather        (~14 MB)
data/body-neurotransmitters-male-cns-v1.0.feather              (~41 MB)
data/optic-column-type-assignments-v1.0.xlsx
```

**许可：CC-BY 4.0** —— 引用时请注明 Janelia Research Campus / FlyEM。

### 3. 预处理（生成 `graph/`）

```bash
python -X utf8 step0_cells.py       # 细胞普查
python -X utf8 step0_mb.py          # 蘑菇体 KC/MBON/DAN
python -X utf8 step1_build.py       # 构图
python -X utf8 build_optic_map.py   # 复眼投射
python -X utf8 build_mb_groups.py   # 蘑菇体分区
python -X utf8 build_motor_axes.py  # 运动轴标定
```

产物约 200 MB，放在 `graph/` 和 `out/`（都不进仓库）。

### 4. 跑

```bash
python -X utf8 endfield_fly.py --panel --tune-port 8791 --hz 2.5 \
    --motor pop --eye main --eye-hz 30 --overlay \
    --forage --evac --combo --skill-auto --ult \
    --attack-hold 1.0 --out out/run.csv
```

或者双击 `start_fly_worker.cmd`。

**游戏里按 `End` = 暂停**（原地暂停，点面板「启动」接着跑）。

## ★ 用之前必读

### 绝对不要有窗口压在游戏上面

程序抓的是**屏幕**，不是游戏窗口（DirectX 游戏拿不到窗口画面）。
任何压在上面的窗口，果蝇都会把它当成"游戏画面"读进去 ——
而且**不报错、不崩溃、只是那个功能永远不触发**。

实测踩过的坑：

| 被挡的区域 | 症状 |
|---|---|
| 连携技搜索区 | E 键永远检测不到 → 永远不放连携技 |
| 血条 | 血量读不到 → 自动挨打失效、大招永远不放 |
| 任务完成横幅 | 打完副本不给奖励 |

**三个症状看起来毫不相关，根因是同一个。**
程序启动时会**自动检查并警告**。

### 分辨率

**任意**，程序自己适配。实测覆盖：
1280×720 / 1600×900 / 1920×1080 / 1920×1200 /
2560×1440 / 2560×1080 / 3840×2160 / 1680×1050

所有标定都是**归一化坐标 + 模板按分辨率重采样**。

### 键位要对得上

面板最上面常驻一行「键位」。和游戏里不一致的话它会一直按错键。
（这一行是踩了一个坑之后加的：`ttk.Combobox` 悬停时会被**鼠标滚轮**改值，
结果 `combo_key` 被静默改成 `q`，连携技永远按错、提示不消失、每拍都按。）

## 已知限制

- **必须管理员权限**，否则键鼠注入完全不生效
- **不能有窗口遮挡**（见上）
- **副本完成检测默认关闭** —— 三版判据（横幅模板 / 颜色 / 文字消失）
  都在录像上零误报、实机上都误触。根因是**"靠屏幕判断游戏状态"这条路本身**
  不可靠：UI 状态空间太大。要试的话加 `--mission`。
- **连携技只认 E 徽标** —— 游戏里不同角色的连携技可能绑不同键，
  但提示徽标本身画的是当前该按的键
- **Interception 驱动**需要签名/LoadDriver 权限，某些企业策略下装不上

程序仍能运行，只是需要用户自己重新标定（用 `ef_combo_collect.py` / `rec_combo.py`）。
